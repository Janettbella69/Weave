# Weave · 住在微信里的习惯助理

**走进你真实的生活。**

Weave 是一个帮人坚持习惯的个人助理（Personal Agent）。习惯发生在一天里的各个角落：上班路上、午休、睡前，还有你和朋友的打卡群。所以 Weave 待在你每天用的微信里，不用你另装一个 App。你说一句话，它就记下；你定下的目标，它帮你拆成今天的一小步；它每天会看看你的进展，值得开口的时候才开口。

适合想养成一个小习惯的人，也适合已经在打卡群里互相监督的人：一起考研的，一起读书的，一起减脂的。

**技术上：** 底层是 Anthropic 的 Claude Agent SDK，和 Claude Code 用的是同一套工具、Agent 循环和上下文管理（官方原话：「the same tools, agent loop, and context management that power Claude Code」）。在这之上，Weave 加了看得见的长期记忆和会自己醒来的主动性，详见下方「技术架构」。

**线上地址：** <https://weave.azorashopping.site/>（目前是单用户试用，进站需要访问密码）

## 一天里的 Weave（示例）

| 时间 | 发生了什么 |
| --- | --- |
| 10:00 | 它看了看你今天的进展。没什么要说的，就没有出声。 |
| 12:40 | 你在微信里说「中午走了 15 分钟」，它记成做到了。 |
| 19:30 | 你说过晚上要读书，现在还没有记录。它问一句：「读了的话回我一下，我帮你记上。」 |
| 20:15 | 打卡群里有人 @ 它。它只根据这个群里的消息回答。 |
| 21:00 | 过了你允许打扰的时段，它不再主动找你。 |
| 第二天 | 它记得昨天说好的事，接着聊。 |

## 它解决的问题

习惯坚持不下来，常常卡在下面四个地方。

### 习惯在生活里，记录却在 App 里

**问题：** 走路、早睡、读书都发生在 App 外面，打卡工具却要你专门打开、点格子、填表。一忙，记录先断；断了几天，就不想再打开了。

**Weave 这样做：** 在微信里说一句「中午走了 15 分钟」，它就记下，网页上的待办点一下也行。记录页给每个习惯一张月历：这个月做到几天，最长连续几天，有几次连着错过两天。《掌控习惯》说偶尔错过没关系，别连着错过两次，所以它专门数这个。

### 目标很大，落不到今天

**问题：** 「今年瘦下来」「多读点书」很难变成今天要做的一件事。《掌控习惯》的办法是把习惯缩到两分钟就能开始，接在每天本来就会做的事后面。道理不难懂，难在没人陪你拆。

**Weave 这样做：** 选一类目标（健康、人际关系、财务、事业、兴趣爱好、效率或其他），和它聊几句，它帮你拆成每天的小习惯：你想成为什么样的人，在什么时候做，最小的一步是什么。目标页上，每个目标挂着自己的小习惯，这周做了几天一眼就能看到。

### 提醒不知道你今天过得怎么样

**问题：** 闹钟到点就响，不管你做没做、忙不忙。响多了，提醒被划掉，习惯也跟着断了。会主动说话的 AI 助理，又常常说得太多。

**Weave 这样做：** 先看，再决定说不说。它按你选的档位每天看几次你的进展，没有值得说的就不开口。它只在你允许的时段找你（默认早 9 点到晚 9 点，按你所在的时区），每天主动说的话有上限；连着两句你都没回，它就先不再定期来问，等你开口再恢复。想调整，在聊天里说一句，或者在助理主页点「多找我一点」「少找我一点」「别主动找我」。它看过却没打扰你的那几次，也会记在「动态」里。

### 一个人难坚持，打卡群又没人管

**问题：** 很多人已经在用打卡群互相监督，考研、读书、减脂都有。可群主要催进度、要统计谁做了，成员要自己记，时间一长，群很容易冷下来。

**Weave 这样做：** 把 Weave 拉进打卡群，@ 它就回答。它只看这个群里的消息，碰不到任何人的个人资料。接下来，群里发一张打卡照片就能记成打卡，不用再 @ 它。

## 它怎么开口

主动找人，是助理最容易惹人烦的地方。Weave 在后台醒来时，按这几条规矩决定说不说、怎么说：

- 大多数时候不开口是对的，拿不准就不说。
- 值得开口的时候很少：你说过要做的事，时间过了还没有记录；或者有件事过了今天就没意义了，比如今天做了，就是连续第 7 天。
- 要说只说一句，最多问一个问题。不批评，不比较，不催第二遍。你没回，不等于你不在乎。
- 没有记录不等于没做，所以它会给台阶：「走了的话回我一句，我帮你记上。」
- 断了不算失败。每周回顾时，它先说你做到的，再说一个最容易改的地方。

这些规矩的原文写在 Weave 的技能（Skill）文件里。

## 走进生活，先守住边界

一个助理要进到你的微信、进到你和朋友的群里，先得让人放心。

- **记住什么，摊开给你看。** 它记住的东西写在一个 `MEMORY.md` 文件里，原文就在助理主页。每天结束时，它把答应你的事、没聊完的话写进交接笔记，第二天接着聊。
- **回复只发给找它的人。** 消息发给谁由后台决定，模型自己选不了收件人。
- **群里看不到个人。** 在打卡群里，它只读这个群的消息，碰不到任何人的目标和记录，成员只显示成「成员1」这样的编号。群消息加密保存，最多留 50 条、14 天。
- **规矩写在后台。** 每天主动说几句、同一句话不重发、晚了两小时的提醒不再补发到微信，这些都由后台规则管，不靠模型自觉。
- **数据你说了算。** 可以导出，也可以删除账号。[隐私说明](https://weave.azorashopping.site/privacy)写清楚了哪些内容会发给模型（DeepSeek）来生成回复，哪些会发给判断模型 Jev。

## 怎么知道它真的有用

**用得越久，它主动说的话应该越少，你做到的天数不往下掉。** 这是我们最想看到的一条线。评测从真实对话里攒题，由人来判对错，看四件事：该不该开口，记得对不对，有没有说出不该说的，有没有声称做了其实没做。

## 技术架构

### 一句话

Weave 是一个个人 Agent（Personal Agent），底层是 Anthropic 的 **Claude Agent SDK**：和 Claude Code 是同一套工具、Agent 循环和上下文管理。所以 Weave 的架构和 Claude Code 一样：一个 Agent、一个循环、按需调用工具。在这之上，它多了两样东西：长期记忆和主动性。

产品要走进用户真实的生活，技术上靠三根柱子：

- **一个 Agent，长在微信里**：网页、微信私聊、打卡群，所有入口叫醒的都是同一个 Agent，每次都是 Claude Agent SDK 的一次 `query()`。
- **长期记忆**：它对这个人的了解，存成看得见的文件。
- **主动性**：没人找它的时候，它也会自己醒来看一看；后台叫醒之前，先由决策模型 Jev 判断值不值得。

### 底层：Claude Agent SDK

Weave 所有的 Agent 行为都走 Claude Agent SDK 的 `query()`。全仓库只有 Agent 服务一个地方调用它，没有第二条直连模型的路。Agent 循环、工具调用、会话、权限、钩子都由 SDK 提供；Weave 自己的代码只做三件事：叫醒 Agent、在工具后端守规则、记账。

| SDK 提供的 | Weave 怎么用 |
| --- | --- |
| Agent 循环（`query()`） | 每次唤醒跑一轮。调什么工具、调几次、用不用技能，都由模型决定，不设轮数上限 |
| 内置工具 | Bash、Read、Write、Edit、Glob、Grep、Skill 每一轮都在，本人那一轮另有 WebSearch。Agent 用 Bash 写 SQL 查快照、跑统计脚本，用 Edit 改 `MEMORY.md` |
| MCP 工具 | weave 自己的 8 个写工具（发消息、存目标、存习惯、记完成、设提醒、排跟进、取消、改档位），在 Agent 服务的进程里执行，转回网站后端 |
| 技能（Skill）和插件 | `proactive-judgment`（后台醒来要不要开口）、`weekly-review`（每周回顾，带一段统计用的参考代码），从只读的插件目录加载 |
| 会话 | 同一个当地日期 `resume` 接着同一段会话；后台那一轮用 `forkSession` 分叉，跑坏了也碰不到聊天那段 |
| 权限 | `permissionMode: 'dontAsk'` 加允许清单：没人在场，不在清单上的工具直接拒绝，不弹确认 |
| 钩子（Hooks） | `PostToolUse` 和 `PostToolUseFailure` 都挂上，每次工具调用都留记录 |
| 费用熔断 | `maxBudgetUsd`：本人一轮 $2、群 $1 |
| 自定义启动 | `spawnClaudeCodeProcess` 把 SDK 背后的 claude CLI 放进每轮一个的一次性容器 |
| 配置隔离 | `settingSources: []`、`strictMcpConfig: true`：不读任何文件里的配置，防止 Agent 改了配置影响下一轮 |
| 子 Agent | 只留给深度研究（还没上线），平时不给 |

**模型怎么接：** SDK 说的是 Anthropic 的接口格式。容器里的 `ANTHROPIC_BASE_URL` 指向 Weave 自己的模型代理，代理换上真 Key，转给 DeepSeek 的 Anthropic 兼容接口。国产模型（Kimi、GLM、千问）也都用 Anthropic 格式的地址加 Key，不用 OpenAI 格式。

**版本：** 钉在 `@anthropic-ai/claude-agent-sdk` 0.3.316。官方写明不支持把 Claude Code 经网关接到非 Claude 模型，所以每次升级前先跑 43 项探针（本地假模型，不花钱）和一次真接口冒烟。

### 整体结构

```text
入口：网页 / 微信私聊 / 打卡群里 @ / 服务器闹钟
   │  微信经 wx 守护进程和微信桥接进来
   ▼
Weave 网站：页面、数据库、业务规则
   │  只决定该不该叫醒，不决定醒了做什么
   │  后台叫醒前 ──► 决策模型 Jev：现在值不值得找用户
   ▼  叫醒，带一张只对这一轮有效的通行证
Agent 服务：唯一调用 Claude Agent SDK 的地方
   │  weave 工具转回网站后端执行
   │  模型代理换上真 Key，按 token 记账
   ▼  每轮起一个一次性容器
Agent 容器：用完即删，没有网络
   │  claude CLI（SDK 背后的执行内核）：模型循环 + Bash、Read、Write、Edit、Skill 等
   │  长期记忆：这个人的工作目录
   │    MEMORY.md 长期的事 / HANDOFF.md 昨天的交接
   ▼  只能经模型代理出去
DeepSeek（Anthropic 兼容接口）
```

### 柱子一：一个 Agent

没有用 LangGraph、LangChain、Dify 这类编排框架。代码里没有流程图，也没有「用户说了 X 就走 Y」。用户今天说「走了 20 分钟」，Agent 记一条完成，回一句。明天问「上个月我哪天最容易断」，还是这个 Agent：自己写 SQL 查记录，用 Python 算一算，再讲结论。第二件事不用新写任何流程。

一条消息的经过：

1. 网站先存下消息，签一张只对这一轮有效的通行证，然后叫醒 Agent 服务。
2. Agent 服务凭通行证向网站取数据，写成一个 SQLite 快照。快照里有目标、习惯、完成记录、提醒、排期、主动设置；群里那一轮只有这个群的消息。然后它起一个一次性容器，跑 SDK 的 `query()`。
3. Agent 自己决定怎么做：查快照，跑代码，用技能（Skill），调 weave 工具记一笔或发消息，更新 `MEMORY.md`。
4. weave 工具只是一层薄壳，规则都在网站后端。同一次工具调用重放时，原样返回上次的结果，不会记两条、发两次。
5. 最后一段话就是回复。网页直接显示；微信的回复排进发送队列，由桥接发出去。
6. 出错不自动重试，因为这一轮可能已经记过东西、发过消息。没拿到完整结果，就如实告诉用户结果不确定。

设计原则：

- 代码只守规矩，不替 Agent 做决定。代码可以说「这个不允许」，不能说「接下来做这个」。
- 东西放哪，按这个分：
  - 必须成立的规则，做成工具（MCP）。
  - 做事的方法，写成技能文字。
  - 每次都要算对的，比如连续天数、周报，写成参考代码放进技能。
  - 只用一次的，当场写代码。
  - 底线，写进系统提示。
- 读用 SQL，写用工具（《Agent Harness 教材》p.16「查数留SQL,不要封成MCP」）。快照每轮重建，在容器里只读。
- 私人资料、不可信内容、对外通道，三样不同时出现在一轮里。
  - 本人那一轮有私人资料，但收件人由通行证决定，只能发给本人。
  - 打卡群那一轮看不到任何人的私人资料，只有一个 `send_message`，只能发回这个群。

### 柱子二：长期记忆

记忆就是文件，不另建记忆系统。每个人在 Agent 服务里有自己的工作目录，记忆分四层：

- **长期的事：`MEMORY.md`。** 里面是这个人的目标、什么对他有效、什么没用、什么让他烦。每次醒来都放进系统提示；Agent 学到稳定的事实，就用自带的 Edit 改它。用户在助理主页的「记忆」栏能看到原文。
- **昨天没做完的：`HANDOFF.md`。** 一天过完，服务器闹钟叫醒一轮收尾。Agent 把说好的时间、答应的事、没聊完的话写进去，第二天放进系统提示（教材 p.47「Handoff ≠ 记忆」）。什么时候收尾由代码定，写什么由 Agent 定。
- **今天聊过的：当天的会话。** 同一个当地日期接着用同一段会话，第二天开新的，上下文不会无限变长。
- **要准确的事实：数据库。** 目标、习惯、完成记录、提醒存在网站的数据库里，网页显示的就是这一份。Agent 只能通过工具写，读的是叫醒前的快照。这一层要求准确，所以不交给 Agent 自由改写。

长期记忆和主动性是连着的。后台醒来时，Agent 先读 `MEMORY.md` 里什么对这个人有效、什么让他烦。用户说过不想被打扰的时间和方式，以 `MEMORY.md` 里写的为准。

打卡群也有自己的工作目录和 `MEMORY.md`，里面只有群里的记录，14 天清理一次，关闭打卡群就删掉。

为什么用文件：

- 用户看得见。
- Agent 用自带的 Read、Edit 就能读写，不用另学一套接口。
- 和 Claude Code 的记忆是同一个做法。

还没做的：

- 用户在网页上改、删记忆。
- `HANDOFF.md` 在网页上还看不到。
- 聊天记录还没放进快照，所以跨天时只能靠 `HANDOFF.md` 接上。这是审查发现的断片根子，已经排进重建。

### 柱子三：主动性和决策模型 Jev

什么时候醒：

- 有人直接找它：网页、微信私聊、群里 @。
- 服务器闹钟到点：Agent 服务每分钟敲一次网站，处理它自己排的跟进，或者按档位定期看看（低、中、高分别是每天 1、2、4 次）。
- 换日收尾。

后台要不要主动找用户，分三道关：

1. **网站的规则。** 先看档位开着吗，在允许的时段吗，今天后台醒的次数用完了吗，用户是不是连着两句没回、或者 7 天没来（教材 p.20「Agent 启动之前 预处理」）。
2. **决策模型 Jev。** 规则都过了，再问 Jev 一个是非题：「现在值不值得主动找用户」。它回一个 0 到 1 的分数，低于阈值（默认 0.5）这次就不叫醒，记一笔 `jev-quiet`。这样拦下的几次，不用叫醒一整轮 Agent。Jev 连不上，就照常叫醒，交给 Agent。
3. **Agent 自己。** 醒了说不说、说什么，由 Agent 按技能 `proactive-judgment` 判断：大多数时候不开口是对的，拿不准就不说。只有调用 `send_message` 才发得出去，不调用就是没开口。后台那一轮从当天的会话分叉出一段新的，跑坏了也碰不到用户聊天的那段。

Jev 的边界：

- 发给 Jev 的是整理过的事实，不是聊天原文：习惯名和今天做没做、最近 7 天做了几次、跟进的备忘、今天主动说了几句、用户多久没说话、有几句主动的话还没回。
- 它只决定要不要叫醒，不决定醒了说什么，也不审 Agent 写出来的话。在新架构里，这是唯一不走 SDK 的模型调用。
- 用户自己让设的提醒不经过 Jev，到点照常发。
- 现在的状态：2026-11-16 起经 OpenRouter 在线上启用，每次判断约 $0.00003。阈值 0.5 是草稿数字，要等攒了真实的「该不该开口」标注再定。

### 安全和费用

- 每轮一个用完即删的容器：没有网络，去掉全部权限，根目录只读，平时不给 WebFetch 和子 Agent。模型请求经 Unix socket 走到模型代理，「Bash 连不了网」靠结构保证。
- 真的模型 Key 只在模型代理里，容器只拿一轮一换的运行令牌。
- 不设轮数上限（教材 p.22、p.26）。兜底只有两样：
  - SDK 的费用熔断：本人一轮 $2、群 $1。这是 SDK 的估价，不是实付。
  - 每轮 10 分钟超时。
- 模型代理按 token 记账：每个账号每天 40 万，全站每天 600 万（草稿数字）。用完返回 429，这一轮马上结束。
- 同一个人的消息排队处理；线上同时只跑 1 轮。
- 微信这条路：网站没收下的消息，桥接不往下读；要发的消息留在队列里，不丢，也不重复发。
- 费用估算：用 deepseek-flash，每轮约 $0.003 到 $0.006，一个活跃用户每月约 $1 到 $2。用真接口跑过一次冒烟，每次模型调用约 4,600 token，和估算对得上。

### 模型和部署

- 模型：DeepSeek，默认 deepseek-flash，也支持 deepseek-v4-pro。模型表里还有 Kimi、GLM、千问，还没用真 Key 跑过。
- 部署：一台腾讯云服务器，用 docker compose 跑网站和 Agent 服务。微信的 wx 守护进程和桥接也在这台服务器上。wx 守护进程用的是开源客户端 agent-wechat，不是官方接口，所以只用小号。整站有访问密码，内部接口各用各的令牌。
- 测试：行为测试、容器契约测试和部署冒烟，每个 PR 都在 CI 里跑。测试里的模型和微信是假的，验证的是规则对不对，不是建议好不好。

### 现在的短板（2026-11-04 全代码审查）

前提变了，骨架没跟着变：

- 网站还用开发工具 wrangler dev 在自己的服务器上模拟托管平台，为此垫了约 2400 行，内存问题也出在这一层。
- Agent 一轮跑几十秒，骨架还是一串挂着等的请求，11 个超时靠手工对齐。
- 「一轮」只是散在 9 个文件里的开关，有六种轮、两个说话出口。
- 没有运行记录和评测（教材 p.63「看不见过程，好坏都是运气」）。
- 数据是一整份加一把全局锁，还没有备份。
- 微信小号的登录每 72 小时被作废一次；消息一路只认文字，所以看不了图。
